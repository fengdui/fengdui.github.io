窗口划分：将一个完整的统计时间窗口（例如1秒）平均划分为多个更小的时间格子。例如，1秒窗口分为2个500毫秒的格子。

时间对齐：每个格子都有其明确的起止时间范围。请求到来时，系统会根据当前时间戳精准定位到对应的格子。

计数更新：对定位到的那个格子的计数器进行原子性的增加操作。

逻辑滑动：当时间推进到当前格子范围之外时，系统会自动创建新的格子来承载新时间段的请求，并可能淘汰或复用最旧的那个格子（取决于实现）。

统计计算：要获取当前整个窗口的指标（如总通过数），系统会累加所有未过期格子内的计数。这个总和就是“最近1秒”的实时流量。

当请求到达 Token Client 时，若为集群限流规则，则向 Token Server 申请 Token。

Token Server 维护一个 全局计数器（如令牌桶或滑动窗口），记录已使用的配额。 收到申请后，检查剩余配额： 若有剩余，则分配 Token，计数器减少。 若不足，则拒绝申请，触发限流。

客户端响应 若获取 Token 成功，则放行请求。 若失败，则触发降级策略（如抛出异常、返回默认值等）。
