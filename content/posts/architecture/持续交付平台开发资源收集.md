某个参考方案：  
整个微服务项目的jenkins pipeline + k8s + helm ci：   
编写或修改通用helm chart
使用gitlab ci参考官方示例为这个helm chart创建一个简单helm仓库  
jenkins pipeline使用helm镜像启动  
使用这个chart生成一个环境  
接下来就是单个模块的ci  
单个模块的jenkins pipeline + k8s ci：  
gitlab代码提交  
jenkins触发构建  
拉取pipeline构建代码（只传几个经常变动的参数）  
jenkins kubernetes plugin 创建一个jenkins从节点pod，以下在从节点进行  
调用 jenkins pipeline shared library 通用maven构建代码  
拉取kubectl配置、maven配置文件等基础环境配置  
mvn编译项目  
maven中的jib插件自动生成一个docker镜像上传到nexus3 docker私服  
k8s deployments滚动替换对应的docker镜像为现在上传的镜像  
java程序在新pod里面启动，一次更新完成  

前端可视化参考:  
前端通过拿到的配置定义，给出可选类型的框图；  
操作者在页面通过拖拽或模板绘图；  
前端保存，后台接收到一个xml格式的字符串，在ApplicationDto的pipelineBpmnXml字段；  
使用dom4j解析xml，得到BpmnGraph对象，并作校验；  
BpmnGraph对象转化为传给pipeline的参数对象JenkinsParamDto；  
在JenkinsPipelineGenerator，JenkinsParamDto使用json序列化，加入groovy语法格式的pipeline脚本字符串；  
pipeline脚本作为job的参数，进入下一个生成job的环节，作为JenkinsFlowDefinition → Definition → script 字段；
