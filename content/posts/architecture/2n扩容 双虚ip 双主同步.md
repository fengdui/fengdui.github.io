1. 2n 扩容与双虚 IP 配置
   在不停机的情况下，通过增加新库并建立同步关系来实现扩容：
- 新增节点与同步：新增与原数据库数量相等的节点，并配置双主同步（Dual-Master Replication），使新库（New）实时同步旧库（Old）的数据。
- 配置双虚 IP：在 Keepalived 或类似高可用组件中，为每一组双主对配置不同的虚拟 IP（VIP）。例如：
- VIP1：绑定在 Old1 和 New1 上。
- VIP2：绑定在 Old2 和 New2 上。
2. 路由规则调整与解除双虚 IP
   当新库数据同步追平后，需调整应用层的路由逻辑：
- 修改路由规则：更新应用端的数据库分片配置（如修改配置中心的 mod 规则），将原本指向旧库的部分流量（例如 id % 4 == 2 或 3 的请求）指向新的虚拟 IP 地址。
- 解除 VIP 绑定：确认流量切换完成后，停止旧库上的 Keepalived 服务，并使用
  ip addr del 命令从旧节点解除 VIP 绑定，确保 VIP 稳定漂移并固定在新主库上。
3. 断开双主同步并实现新库高可用
- 断开同步：在各节点执行 STOP SLAVE; RESET SLAVE ALL; 物理切断旧库与新库之间的双主同步关系，使它们成为独立运作的数据库。
- 建立新高可用架构：为新扩容后的 4 个独立库分别重新配置其从库（Slave），并使用
  Keepalived + HaVip 或云原生高可用组件建立新的主备切换机制，确保扩容后的每一组节点都具备故障自动漂移能力。
4. 删除多余数据
   扩容完成后，每个数据库中都存有全量数据，但实际上只负责原有一半的分片，需清理不再属于该库的数据以释放空间：
- 旧库清理：根据新的路由规则，删除原本属于新库分片的数据（例如旧库只保留 id % 4 == 0，删除 id % 4 == 2 的数据）。
- 新库清理：删除原本属于旧库分片的数据。
- 注意事项：建议在业务低峰期分批执行 DELETE 或通过重命名表的方式平滑清理，防止大量锁表或 IO 负载过高
