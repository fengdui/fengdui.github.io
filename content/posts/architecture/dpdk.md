# 透明网桥
透明网桥是采用物理串接的形式，一般串在交换机与交换机之间或交换机与数据库之间，在串在核心交换机之间时，背景流量很大，需要转发效率很高。
透明网桥模式，采用dpdk来进行流量转发，在转发的同时拷贝一份流量，通过共享内存传递给gateway，即该模式实际属于旁路模式，业务性能不会影响转发效率。
透明网桥模式支持链路阻断，网桥程序内部会维持一个会话表，当收到阻断指定链路的消息时，根据当前链路信息发reset包来进行阻断。该阻断属于事后阻断，可能无法及时阻断。

# DPDK 网桥与 Linux 网桥对比

## 1. 对比列表

| 特性               | DPDK 网桥                                        | Linux 网桥                                        |
|--------------------|-------------------------------------------------|--------------------------------------------------|
| CPU 消耗           | 默认采用轮循模式，CPU 占用 100%                  | 随流量上升，CPU 上升                              |
| 数据包类型转发     | 全自定义模式，可以随意过滤和转发                  | 默认情况不转发 802.1D 相关协议的数据包             |
| 开发难度           | 高，熟悉整套 DPDK 体系                           | 低，使用 brctl 命令建立即可                       |
| 硬件依赖           | 高，需要使用 DPDK 支持的硬件，以 intel 系列网卡为主 | 低，只要 linux 可以驱动的设备就可以使用           |
| 构造阻断数据包难度 | 低，全定义数据包，可在网卡硬件上自定义发送        | 中，包构造不太困难，但是要在桥上发送，比较麻烦    |
| 同异步模式         | 可采用同步或异步模式                             | 只可采用异步模式（串连旁路）                      |

## 2. 802.1D 协议网桥支持情况

LACP 的协议使用 01-80-C2-00-00-0x 范围内的 MAC 地址，这个范围在 IEEE 标准 802.1D 中定义为"MAC 桥接过滤 MAC 组地址"。这是 IEEE 为使用链路本地组播与相邻设备通信的标准协议预留的范围。使用这些 MAC 地址的帧应该是显式链接本地的。

IEEE 维护的协议列表如下：

| MAC 地址            | 协议                                              |
|---------------------|---------------------------------------------------|
| 01-80-C2-00-00-00   | Spanning Tree (STP/RSPT/MSTP)                     |
| 01-80-C2-00-00-01   | Ethernet Flow Control (pause frames)              |
| 01-80-C2-00-00-02   | Link Aggregation Control Protocol (LACP)          |
| 01-80-C2-00-00-03   | 802.1X Port-Based Network Access Control          |
| 01-80-C2-00-00-08   | Provider Bridge protocols (STP)                   |
| 01-80-C2-00-00-0D   | Provider Bridge protocols (MVRP)                  |
| 01-80-C2-00-00-0E   | 802.1AB Link Layer Discovery Protocol (LLDP)      |

当使用 Linux 网桥来连接两端设备时，如果希望网桥尽可能像一根网线一样直接连接两端的设备。很不幸，Linux 桥接器编写得很规范，符合 IEEE 802.1，它过滤了 01-80-C2-00-00-0x 范围内的目标地址所有以太网帧。这意味着 LACP 协议是不会被透传的。

当然，如果的确需要透传 802.1D 协议的某些数据包，有一些解决方案。由于 Linux 内核在 2.6 以后有一个设置，允许通过在 `/sys/class/net/bridge-iface/bridge/group_fwd_mask` 中设置一个特定的位掩码，来控制从 IEEE 802.1D 中定义的桥接器应该转发哪个 MAC 地址的帧。默认值 0 表示 Linux 桥接器不转发任何链接本地帧。

例如，将这个值设置为 16384 将允许桥接转发 LLDP 帧(01-80-C2-00-00-0E)：

```bash
echo 16384 > /sys/class/net/br0/bridge/group_fwd_mask
```

有个问题是：在默认内核发行版中，前三个 MAC 地址(-00、-01 和-02)的位掩码值是受限制的，这意味着我们仍然不能使用这个技巧使 LACP 协议通过网桥转发。要删除这个限制，就需要自己对内核进行补丁并编译。
