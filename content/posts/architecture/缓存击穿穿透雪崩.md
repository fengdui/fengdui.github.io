缓存穿透是指查询一个根本不存在的数据。由于缓存中不存在，数据库中也不存在，因此这个请求每次都会绕过缓存直接查询数据库。如果有恶意攻击者持续用大量不存在的 key 来请求，数据库可能会被压垮。  
缓存空对象 当数据库中也查询不到数据时，我们仍然将这个空结果（比如 null）进行缓存，并设置一个较短的过期时间（例如 5分钟）。  
在缓存之前，设置一个布隆过滤器。布隆过滤器是一个高效的数据结构，用于判断 “某元素一定不存在” 或 “可能存在”。  


缓存击穿是指一个热点 key 在缓存过期的瞬间，同时有大量的请求过来。由于缓存失效，这些请求会同时去查询数据库，瞬间给数据库带来巨大的压力。  
对于极热点的 key，可以设置其永不过期。然后通过后台任务或逻辑，在数据更新时主动刷新缓存。  
当缓存失效时，不是所有线程都去查询数据库，而是使用分布式锁（如 Redis 的 SETNX 命令），只允许一个线程去查询数据库并重建缓存，其他线程等待，然后重新从缓存中获取数据。  

缓存雪崩是指在同一时间段内，大量的缓存 key 同时失效，或者 Redis 缓存实例直接宕机。导致所有请求直接落到数据库上，引起数据库压力过大而崩溃，就像雪崩一样。  
在给缓存设置过期时间时，加上一个随机值，让 key 的过期时间均匀分布。  
通过 Redis 的哨兵模式或集群模式，实现缓存服务的高可用。即使个别节点宕机，整个集群依然可以提供服务，避免因单点故障导致的雪崩。  
在应用层引入熔断机制（如 Hystrix、Sentinel）。当检测到数据库压力过大，或非核心服务不可用时，对请求进行降级处理。  
对所有数据或重要数据设置永不过期，然后通过后台 worker 定时异步地更新缓存。这种方式对架构设计要求较高
