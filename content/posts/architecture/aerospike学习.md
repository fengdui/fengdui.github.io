混合存储引擎  
Aerospike的一个显著特点是其混合存储模型。  
它将所有数据的主索引完全存储在内存（DRAM）中，  
而实际的数据记录则可以存储在SSD或Flash等持久化设备上。  
这样的设计使得数据访问几乎可以达到内存级的速度，  
同时利用SSD的容量和成本优势来支撑海量数据  

数据分布与高可用  
Aerospike通过一致性哈希将数据划分为多个分区（Partition）。  
每个分区都会有一个副本列表（Replica List），列表中的第一个节点作为主副本（Master），  
负责该分区的读写；其余节点作为从副本（Replica），  
通过复制来保证数据可靠性。这种机制确保了即使在节点故障时，数据也不会丢失，并且服务可以快速切换到其他副本，保证了系统的高可用性  

增量迁移  
在节点加入或离开集群，数据需要重新分布时，  
Aerospike采用增量迁移策略。  
节点间会交换分区的版本信息，通过版本比较，只同步有差异的数据，而不是全量拷贝，这大大提升了数据迁移和再平衡的效率。  

``` text
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│  数据节点    │  │  数据节点    │  │  数据节点    │
│ 内存: 索引   │  │ 内存: 索引   │  │ 内存: 索引   │
│ SSD: 数据    │  │ SSD: 数据    │  │ SSD: 数据    │
└─────────────┘  └─────────────┘  └─────────────┘
        自动数据分片和负载均衡
```

Aerospike是面向海量数据的分布式主数据库，强调强一致性和数据安全，采用内存索引+SSD存储的混合架构实现低成本高扩展；原生分布式，自动分片、数据平衡和故障转移 简单的记录-列模型，类似表格  
而Redis是功能丰富的内存数据结构存储，主打极致性能和灵活的数据操作，通常用作缓存、会话存储和消息中间件，其纯内存架构在数据量和成本上存在限制 需要哨兵/集群模式，扩展相对复杂 丰富的数据结构（字符串、哈希、列表、集合等）
