在使用 GraalVM 构建 native 镜像时，对于通过反射、动态代理、JNI 等方式访问的类 / 方法（这些无法在编译期被静态分析识别），需要通过 反射配置文件（reflection-config.json） 显式声明，否则会在运行时出现 ClassNotFoundException 或 NoSuchMethodException 等错误  

尽量精确声明需要反射的成员（而非全量 allDeclaredXXX），避免生成的 native 镜像体积过大。  
若使用 Spring、Jackson 等框架，通常需要额外配置反射（框架内部大量使用反射），可参考框架官方的 GraalVM 适配文档  
spring-native  
https://docs.spring.io/spring-native/docs/current/reference/htmlsingle/  

如果类被配置为 “构建时初始化（Build-Time Initialization）”，那么它的 static 代码块会在 GraalVM 原生镜像的构建阶段（编译时）触发执行；如果是 “运行时初始化（Run-Time Initialization）”，则 static 代码块在镜像启动后（运行时）触发执行—— 这完全由 GraalVM 的类初始化时机配置决定  
构建时初始化 就会提前进行类加载  
spring boot 2.4.13 + spring native 0.9.2 + aot插件 0.9.2 + native-maven-plugin 0.9.18  
这个版本的坑比spring3.0多  
很多框架依赖了很多包 maven的依赖传递 如果运行时没用到没加载是没问题的 但是做native的时候 他就会分析 有些用不到的他也会提前构建时初始化 导致依赖其他类也被提前初始化 但是有些包里面的配置又要运行时初始化 冲突了 需要排掉或者特殊处理 比如  
调试信息显示 io.netty.channel.kqueue.KQueue 类在构建时被初始化，它触发了 AbstractReferenceCounted 的初始化  
<buildArg>--initialize-at-run-time=io.netty.channel.kqueue</buildArg>  
很多运行时需要用到的反射 需要加配置  
打进去的文件识别不出来 比如xml日志文件  
spring condtion配置类 原来是去读配置文件 但是这个是在运行时的 Native Image在构建阶段就尝试解析条件注解 matchIfMissing = true可能在构建时被错误解析 所以很多配置文件要改  
dubbo spi spring spi 需要适配  
GraalVM的封闭世界假设（Closed World Assumption） 静态分析限制： GraalVM只能分析代码中明确引用的资源 无法动态发现ResourceBundle.getBundle("xxx")调用中的字符串参数 需要加 resource-config.json  
-agentlib:native-image-agent=config-output-dir=./native-image-config 收集的不一定全 因为可能运行时压根就不用 但是build又需要  

# spring boot 2.4.13 spring native 0.9.2和aot0.9.2
StaticSpringFactories 是 Spring Native 项目中的一个重要组件，StaticSpringFactories 的作用
1. 替代传统的 SPI 机制 在传统的 Spring Boot 应用中，Spring Factories 机制通过 META-INF/spring.factories 文件来加载各种自动配置类和服务。但在 native image 环境中，由于反射和动态类加载的限制，这种机制无法正常工作。
2. 静态化 Spring Factories StaticSpringFactories 类是在构建 native image 时由 Spring AOT 插件自动生成的，它的主要功能是： 将原本通过 spring.factories 动态加载的类转换为静态代码 提前实例化和注册各种 Spring 组件，如 ApplicationListener、BeanDefinitionRegistryPostProcessor 等 避免在运行时使用反射来加载这些组件
   StaticSpringFactories 的集成机制 StaticSpringFactories不是替换SpringApplication.run()，而是改变Spring Boot加载组件的方式：
```
// 传统的Spring Boot会这样做（使用反射）：
Class.forName("com.utopia.spring.extension.listen.UtopiaApplicationEvent")

// 使用StaticSpringFactories后，会这样做（直接实例化）：
new com.utopia.spring.extension.listen.UtopiaApplicationEvent()
```
